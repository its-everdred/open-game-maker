## Failure history

- #350 records a 500 ms room phase transition timeout in CI run 41532661946. A local unquarantined probe reproduced the failure; a diagnostic run observed the transition after 254 ms. The test now waits for the state in the browser instead of sampling over the process boundary with a 500 ms deadline, and the desktop case has been restored.
- CI run 45929397673 failed the screen-route reservation test for `welcome`; run 45916892196 failed four database migration tests after an extra migration appeared. Both reported assertion failures; these logs alone do not establish whether either is flaky or related to a launch journey.
- #1260 reports a duplicate blob request in CI run 45067049457. The service worker returns the fetched response while its cache write continues under `waitUntil`; the browser test previously navigated to the next build as soon as the response rendered, before that write necessarily finished.
- Local full-suite validation after a build found that `gm-new-game-plan` also collected compiled tests in `dist`, where their source fixtures do not exist. Its test script now excludes compiled output. Two process-heavy test files also exceeded Vitest's five-second default under host contention; their scoped allowances cover the actual Node and Git launches without retrying assertions.
- The local room suite exposed 200 ms reconnection windows in tests expecting success and a late-join listener registered after a 50 ms delivery delay. Those tests now hold the relevant timers or use longer success-path windows; expiry tests retain their short windows. Both affected files passed together after the changes.
- Local post-deploy logs contain 14 New Game runs. The latest, `ed58582f20b1`, exited 1 with missing API, repository, internal token or QA session configuration. The launch plan records earlier timeouts and a 502. The later decisions replace production create/delete checks with local temporary-folder tests (#1402).
- The latest voice log, `2f4c0698b837`, exited 1 after truncated dictation; two-way audio passed. The preceding `aa7366ad9abe` run passed both. An earlier `fe5db11dc45b` run timed out in both paths.
- The latest review log, `328c6688e4ea`, exited 0; `df2f74c14f91` exited 1 when the review-note fill timed out at 820×1180. These historical production observations do not prove local system coverage.
- An exploratory local Blobs draft build needed the workspace SDK's `scenery` export because the game checkout's installed SDK lacked it. A scratch asset build initially failed when the asset tool tried to rewrite the read-only shared library index. With a private index and game copy, the mobile assets and draft bundle built successfully. The existing fixture-backed app-switch test then loaded the manifest and assets but timed out before gameplay; its follow-up reached a hidden flow and did not finish startup. These runs provide no CPU, online, or successful lifecycle evidence.
- A later hosted CPU probe reached gameplay, then failed when the game called `runtime.host.haptics.pulse`: the exploratory bundle mixed the older installed SDK with the workspace `scenery` export. A subsequent scratch build aliased several SDK entry points to the current workspace SDK but initially missed the double-quoted `core` and `camera` imports. A hit-tested run reached gameplay and again failed on haptics; the corrected scratch build includes those imports. A first rerun failed to bind an occupied local port; a dynamic-port rerun reached the host but failed before the menu because the scratch build lacked its separately staged asset blobs. A further run with those assets staged timed out while loading at 85%. A direct-host run with the same assets also timed out during loading at 63%. A later run with both tiers reached gameplay, but was interrupted after exceeding its 20-minute bound; its partial trace showed 11 hard drops and no result. A corrected private build then completed the hosted CPU match at both sizes without page errors; a deliberate break remains pending.


- The local multi-client verifier seated two clients and reached the room playing phase with the scratch Blobs build, but failed during gameplay setup: the scratch asset manifest contained only mobile files and a desktop model could not load. An attempted desktop asset build failed because it pointed at the wrong local blob store; a corrected scratch build produced both tiers, with one ffmpeg job using the builder’s existing retry. A later two-client attempt failed before joining because the rooms service did not start within its 20-second bound under heavy host load. With corrected SDK imports, another run joined both seats but failed taking a screenshot before gameplay. No online gameplay pass is claimed.

- A hosted two-browser Blobs probe connected two seats, but the peer lobby marked the owner as local and offered no local Ready button for the peer. The game’s lobby captures `room.localSeat` at creation and its seat-table update does not replace that field; the room adapter’s `requestStart` is also a no-op. The current test uses fixture-issued grants and is not a production two-device acceptance. A diagnostic run is checking the SDK seat; no online gameplay pass is claimed.

## Deliberate breaks

- Sign-in and permissions: temporarily removing the admin authorization call in the local API made the 390×844 system test fail: the admin endpoint returned 200 instead of 403. The source was restored before the passing run.
- Reviews: temporarily rejecting the local review answer made the portrait system test fail because the verdict and note remained unset. The source was restored.
- Chat: temporarily rejecting the local API chat write made the portrait system test fail because no message was stored. The source was restored before the passing run.
- Dictation: temporarily rejecting the local dictation-token request made the portrait system test fail because no audio reached the provider. The route was restored after the probe.
- Manual editing: before the pointer-events fix, the portrait system test could not tap Night because the game iframe intercepted the lighting palette. The same test passed after the fix and stored a design transaction.
- Minerals/Gas: changing the weekly-refusal response status from 402 to 202 made the portrait system test fail; the route was restored after the probe.
- Host launch, play and pause: temporarily dropping `lifecycle.pause` from the local host bundle made both viewport tests fail as the game clock continued. The bundle was restored for passing runs before checkpoint `bb0a5dfb`; the subsequent native-touch host tests and strengthened app journey passed separately.
- Bug reporting: before #1333, the portrait player journey reached submission but received HTTP 400 and stored no report. After the fix, the same journey passed at both sizes and checked the exact hosted build ID.

The remaining paths still need real-host journeys and deliberate-break evidence. The local sign-in run forwarded auth and API requests to its local server, but the preview's unrelated telemetry beacon attempted its default API port and was refused; telemetry is not covered by that result.
