# Generated sprite library

`gm sprite-forge promote <round-directory>` accepts a round containing `recipe.json`, `asset.card.json`, `collection.card.json`, the PNG named in the recipe, and any referenced mesh. The collection and asset templates must be valid asset cards with IDs `t1:<set>@<version>` and `t1:<set>/<slug>@<version>`. The collection supplies the reviewed license, rights, and compatible set; do not invent rights or verdicts. Set names end in `-generated`. The recipe must record the creator's approval and exact verdict, agent, versioned skills and tools, source card IDs, and hashes. Promotion checks the recorded output and input hashes, writes a new collection under `assets-local/sets/`, and refuses to overwrite an existing asset. Search with `gm assets search --generated`; `gm assets use <id>` references the resulting asset like other catalog assets.

The first supported recipe schema is `ogm.sprite-recipe/1`, for the checked-in Blender iso rig. It records `set`, `slug`, `version`, `scene` (`tile`, `rock`, `cube`, or `hull`), `seed`, numeric `parameters`, `views`, the chosen `output` PNG, `output_sha256`, and `pixel_sha256` (SHA-256 of `<width>x<height>:` followed by decoded RGBA bytes), `rig_sha256`, and the first line of `blender --version` as `blender_version`. For animated output, set `output` to `sheet.png` and add `sheet: {cell, start, end}`; the rig renders 15 frames in eight directions and applies the forge alpha finishing rules. Hull scenes additionally require a relative `input` and its `input_sha256`. Record `materials`, `reference_card_ids`, `prompt` (null when unused), `derived_from`, `agent` (`backend`, `model`, `effort`), `skills` and `tools` (each `{name, version}`), `scores`, `ticket`, `created_at`, `ai_generated`, `approved_by_creator`, and `verdict_quote` for approved work. Record unknown historical facts as unknown; do not assert a version or approval without evidence.

`gm sprite-forge rerun <recipe.json> [--seed N] [--vary shape=1:3:3] [--out directory]` uses the installed rig only when its hash and Blender version match. It checks the source mesh hash and, for an unchanged recipe, checks the decoded pixel hash against the recorded output. Every rerun clears approval and scores and marks its agent and skills unknown until the new run is documented; a seed or parameter change also assigns a distinct slug, so the sibling needs its own review before promotion. `--vary` names an existing numeric parameter and an inclusive minimum, maximum, and count (2–100). Each result has its own recipe. Output directories must not exist already.

Blend files, local modified rigs, and image-generation mocks are not supported by this runner. Retain their original files and provenance; do not relabel them as reproducible with this rig. The current format does not make image-generation services deterministic.

Approved historical rounds can be promoted as `scene: "historical"` when the original replay rig has not yet been captured. Set `archive` to `{record, record_sha256, round, files, gm_rerun_supported: false, created_at_basis: "archive_capture"}`: `record` is the relative original provenance JSON, and `files` lists companion `rebuild_<direction>.png` images with their SHA-256 hashes. The command verifies the record identifies the same round, source, agent, rig, Blender version and output hashes, then copies the record and all views. The card marks the recipe as archival and records that the gm rerun command does not support it; the original local rig remains available for reproduction; `created_at` is the archival capture time, not an invented historical timestamp. `gm sprite-forge rerun` refuses these recipes until the historical rig is captured and verified.
